# Threat Model

## Assets

- Student identity and authenticated school session.
- Personal timetable and calendar data.
- Google OAuth access/refresh tokens.
- Integrity of the user’s Google Calendar.
- Repository and release supply chain.

## Threats and mitigations

| Threat | Mitigation |
|---|---|
| Credential theft | Never request or store school password; user logs in directly on official origin |
| Cookie database exfiltration | No extension cookie permission; no reading browser profile files |
| Session/CSRF leakage | Same-origin requests only; CSRF values remain transient and are not persisted |
| Malicious SIS page | Connector runs only after explicit action; output is schema-validated; no HTML is injected into terics UI |
| Malicious HTML/XLSX | Content sniffing, 10 MiB limit, safe DOM parser, no script execution, XLSX library isolation |
| DOM injection | All Web UI course text is assigned with `textContent`; Tkinter labels/tree rows are data-only |
| Malicious extension message | `terics.extract` message contract validation and normalized-response validation |
| Broad host access | Extension uses `activeTab`, not `<all_urls>` or fixed host permissions |
| Remote code in extension | All bundles local; verifier rejects remote script loading and eval/new Function |
| OAuth CSRF | Google-supported OAuth flows, local loopback state validation, PKCE automatically generated by google-auth-oauthlib |
| Token leakage | Web token memory-only; Python token in keyring; no logs/JSON |
| Calendar mass deletion | Only events with `terics_source=terics` and matching term are considered; empty/incomplete data blocks deletion; final confirmation required |
| Deleting other apps’ events | Planner filters by private extended properties and never bulk-clears a calendar |
| Personal data in logs | No timetable body/credential logging; sync log only counts and local IDs |
| Dependency compromise | Lockfiles, npm audit, license audit, pinned Python ranges, GitHub Actions |

## Residual risks

- A compromised school origin could return malicious content; parsers do not execute content but could produce incorrect fields.
- No dedicated XLSX decompression-bomb quota exists beyond the compressed file-size cap.
- Direct Google sync cannot be accepted as validated until real OAuth/account testing is completed.
- Experimental school adapters may break when the SIS is updated.
- GitHub Pages OAuth availability depends on a correctly configured Google client and authorized `https://styayur.github.io` origin; absence of that configuration safely disables direct Web sync.

## Out of scope

- Bypassing CAPTCHA, MFA or access controls.
- Password cracking, cookie theft or session hijacking.
- Automatic course selection, withdrawal or any write operation to the school SIS.
- Background monitoring.
