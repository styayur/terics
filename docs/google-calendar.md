# Google Calendar

terics has two separate paths:

1. **Offline ICS** — always available, no Google configuration required.
2. **Optional incremental sync** — uses official Google OAuth and Calendar API, only when a client ID/account is configured by the user.

Real-account sync was **not verified** in the v0.5.0-rc.2 release environment. The code path and deletion safeguards are mock-tested.

## Offline ICS

1. Open [Google Calendar](https://calendar.google.com/).
2. Settings → Import & export.
3. Upload the `.ics` generated by terics.
4. Select the destination calendar.

ICS uses `TZID=Asia/Shanghai`, CRLF and UTF-8-safe line folding.

## Web OAuth

Build-time environment:

```text
VITE_GOOGLE_CLIENT_ID=...
```

The Google Cloud OAuth web client must authorize the actual origin:

```text
https://styayur.github.io
```

No client secret is used by the static Web app. The access token is held in memory and is not written to localStorage or timetable JSON. If no client ID is configured, the Web sync panel is visibly disabled and ICS remains available.

Scopes:

```text
https://www.googleapis.com/auth/calendar.app.created
https://www.googleapis.com/auth/calendar.calendarlist.readonly
```

`calendar.app.created` allows terics-created secondary calendars and their events. The Web UI only records/selects calendars created as `terics / …`; it does not claim access to arbitrary calendars.

## Python Desktop OAuth

Desktop OAuth client configuration:

```powershell
$env:TERICS_GOOGLE_CLIENT_ID = "..."
$env:TERICS_GOOGLE_CLIENT_SECRET = "..."
```

or a standard Desktop OAuth client JSON file:

```powershell
$env:TERICS_GOOGLE_CLIENT_CONFIG = "C:\path\to\desktop-oauth-client.json"
```

The installed-app flow uses a `127.0.0.1` loopback redirect. `google-auth-oauthlib` generates PKCE state by default. Refresh credentials are stored in the operating-system keyring through `keyring`, not plaintext config.

The GUI provides **清除 Google 授权** to remove the keyring token.

## Incremental sync model

A sync plan is computed before any write:

- create events missing from the managed set;
- update managed events whose schedule hash changed;
- skip unchanged events;
- list stale managed events as deletion candidates;
- never touch events without `terics_source=terics` and the current term ID.

Private extended properties:

| Key | Purpose |
|---|---|
| `terics_source` | Must equal `terics` |
| `terics_course_id` | Stable course ID |
| `terics_meeting_id` | Stable meeting ID |
| `terics_event_uid` | Stable event UID |
| `terics_schedule_hash` | Change detection |
| `terics_adapter_version` | Adapter version |
| `terics_term_id` | Term isolation |

Safety rules:

- Empty new timetable → no deletes.
- Failed validation → no sync.
- Delete candidates require a second explicit user confirmation.
- No background automatic sync.
- No write to other applications’ events.
- API requests use pagination and retry on 429/5xx.
